# BYDP「博弈点评」设计标准 v1（F2「精密仪器」）

> 2026-09-23 PO 通过（暂定）。P1 所有页面按本标准执行；改动本文件须 PO 裁定。
> 基线画板：F2-01 首页（`hifi/HomeV7*.dc.html`）。

## 1. 定位一句话
成熟的精密感：克制、准确、机械动效。年轻感来自精度而非张扬。**不是**：陈旧（A）、盘口式黑+霓虹（B/C）、编辑杂志质感混淆（D）、玩具感 3D（E）。

## 2. 六条硬规则
1. **看的 / 按的分明**：全站唯一按钮质感 = 实心酒红胶囊 `btn`（PO 2026-09-23：墨色按钮被多人反馈压抑，改为酒红；日夜均为白字）；内容永远是发丝框面板。禁止把内容做成按钮质感，禁止把按钮做成卡片。
2. **状态色只出现在数据上**（数字、指针、区带、标签框），不用于装饰、背景、大面积填充。
3. **一色强调**：电蓝 `#2B5CFF`（夜 `#7A93FF`），只用于：光标、实时点、链接、活动 Tab 指示、扫描线。
4. **无阴影、无叠圆角、无渐变洗底**。深度靠发丝线、点阵底纹、四角刻线。
5. **表盘是全站核心可视化**：品牌页大表盘、名单页小表盘阵列、查询结果页指针落点。黑名单不计分：指针压死 0 且变红。
6. **每个信任信号必须标注 `实体.字段`**（架构 §7）；给不出数据的不画。

## 10. 文字层级与列表规范（2026-09-23 PO 指出后定死）
- **列表条目正文降级**：条目内说明句、条款行一律 body/muted 12–13px，禁止 ink 14+（优惠页「密集黑字眩晕」教训）。
- **三级文字色**：`ink` 标题 / 主体名 / 关键数字；`body` 正文说明（日 #3A3F4A · 夜 #C3C7D1）；`muted` 眉题 / 时间 / 单位 / 辅助。**一行内只允许一个 ink 焦点**，其余必须降为 body 或 muted——禁止整行黑。
- **列表行结构**：`[时间或序号 muted] [主体 ink 600] [说明 body 400] … [状态标签]`；行高 38–40；行间发丝线 `line`；单行截断用省略号，不换行。
- **榜单类**（热查、排行；**首页模块标题用「近期被查询较多」**，不用「热门黑盘」等暗示性措辞——被查询与否与是否有问题无关，审核 D-016）：必带序号列（14px 宽，muted）+ 发丝分隔 + 右侧计数带单位（"43 次"）。
- **状态标签**：框线式，色 = 状态色，字号 10–11；黑名单唯一允许实底反白。
- **模块标题三层**：眉题 muted 10–11 大写字距 → 中文标题 ink 16 → 副题 body/muted 12，右上角元信息 accent 链接。

## 11. 文字密集页八技法（2026-09-23 PO 要求保留复用）
按「先砍、再分、再藏、最后换形」顺序使用：
1. **渐进披露**：默认只露结论层；列表默认 2 条 + 「展开全部 N 条」；一屏只放一个决策所需信息。
2. **倒金字塔分层**：每模块 = 一个结论 + 1–2 个支撑数字；解释句移到二级页 / 展开区；与数字格重复的摘要段删除。
3. **图形替代文字**：时间线 / 置信度 / 状态用可视化，文字只做标签；条目 = 日期 · 4 字动作 · 可选一句说明。
4. **分 Tab 不堆叠**：「回答」与「证据」分离；证据类内容用 Tab 或折叠段，一次只看一段。
5. **密度节律**：高密度块（数字格）与低密度块（一句判定）交替；正文行高 1.6、段间 8、模块间 12；同色文字连续 > 3 行即换形式。
6. **单焦点扫读**：每模块一个 ink 焦点（§10），全页扫读停留点 ≤ 6。
7. **手势承载细节**：长按格子出释义、点标签出依据、展开手势出说明——解释不占版面。
8. **数字先于文字**：能用「< 30 天」就不写「不足 30 天，属新域名」。

实施口径（PO 2026-09-23 通过）：所有内容页组件带 `dense` 开关，**默认 true**；列表默认 2 条、说明单行 18 字截断、建议折叠；完整版仅作展开态。本节技法为项目级规范，后续所有页面按此执行。
- 四角刻线用独立类名 `c-tl/c-tr/c-bl/c-br`，禁与时间线 `.tl` 等布局类同名（原型 v1 类名冲突事故：刻线被撑宽并多出竖线，压住眉题）

## 12. 密度回调 · 品牌卡 · 可点性（2026-09-24 投资人反馈后定）
**密度**（v1 过密、展开过多、无轻重）：
- 间距上调：模块间 12 · 模块内边距 14 · 列表行高 ≥ 48 · 格子内边距 10；`dense` 仍为默认，但列表默认 **3 条**，剩余 ≤ 1 条时直接全显、**不出展开**；展开控件降为右对齐 muted 小字「还有 N 条 ›」。
- **两级模块**：一级 = 发丝框面板 + 四角刻线（结论、品牌卡、评分）；二级 = 无框 `.sec`（动态、热查、统计行），靳靠标题与发丝行分隔。一页一级模块 ≤ 3，一二级交替形成节律。
- 解释/建议文案不再折叠，直接以 muted 12 段落置于动作区下方。
**BrandCard 组件**（所有品牌出现处复用：首页认证推荐、查验结论、品牌页头、名单行、案件页、我的绑定、优惠条目）：
- 结构：Logo 44（P1 用首字字标，`Brand.logoUrl` 为 gap #7 待补）· 名称 ink 16/700 · 状态标签 · 官方域名 mono muted 11 带 globe 图标（`Identifier(type=domain, ownership=official, primary)`）· 分数 22 mono（可关）。
- 出口：certified → 酒红「前往官网 ↗」+ 「领专属码」；watch → 描边「前往官网 ↗」+ amber 风险行；blacklist / fake → **无出口**。
**可点性（affordance）**：入口格 = 线性图标 + 右上 ↗；可导航行 = 行尾 › chevron；文字链 = accent + ↗；动作 = 酒红 btn；纯展示元素三者皆无。触控目标 ≥ 40px。
**图标**：单色线性 1.5–2px 描边、16–18px、随 ink/muted 取色、不上状态色；只用于入口 / 分类 / 导航 / Tab，不做装饰。禁止彩色拟物 / emoji 风（E 版教训）。

## 13. 主执行版 = 方向 R「暗夜雷达」（PO 2026-09-25 暂定）

- **主题矩阵**：色系 `accent ∈ green 雷达绿 #C6FF4A | blue 冰蓝 #5AD8FF | gold 香槟金 #F2CF6B` × 底色 `bg ∈ night #07090C | dusk #161B23 | day #F3F5F8`，共 9 组，全部由 CSS 变量驱动（`data-accent` / `data-bg` 挂 `<html>`）。日间模式下强调色自动换深色变体保证对比度。默认 `green × night`。
- 状态色（认证绿 / 观察琥珀 / 黑名单红 / 仿冒紫）**不随色系变化**，只用于数据。

- 视觉语言：玻璃面板（glass + 1px 边 + blur）、单强调色荧光、评分环替代表盘、雷达扫描、预警 ticker、Bento 数据块、横滑竖卡（品牌卡 = Hero Logo → 名称/分数/徽章 → 优惠框 → 前往官网 → 看评测/条款）、悬浮胶囊导航。

## 15. 登录页（2026-09-29，为 A-009 补设计；原型 `login` 页）
- 结构：品牌标 + 标题「登录后解锁 领码 · 投诉 · 赔付资格」+ 一句「不设密码」→ 玻璃卡：**Telegram 一键登录（accent 主按钮，官方组件回调模式）** → 副注「不会拿到你的手机号」→ 分隔「或用邮箱」→ 邮箱输入（fld）→ 描边按钮「发送登录链接」→ 条款/18+/大陆声明。
- 状态：`sent`（邮件图标、掩码邮箱、15 分钟一次性、发件人、重新发送倒计时 60s、换个邮箱）；错误态三种（格式 / 限流 10 分钟 / 地区 451）为输入框红边 + 行内红字，不弹窗。无论邮箱是否已注册，`sent` 文案一致。
- 我的页：普通「退出登录」只退本设备；「退出所有设备」红字描边按钮，触发 epoch+1。

## 16. 我的页三个二级页（2026-09-29，原型 `bind` / `rg` / `privacy`）
- **添加绑定**：选平台（仅认证 / 观察库，卡片式单选，含 Logo · 域名 · 徽章）→ 账号输入 + 来源 chip（经 BYDP 领码 / 手动）→ 隐私说明（只存哈希、同一账号仅一人可绑）→ 提交 → `done` 态：「已提交 · 自报级」+ 升级为回传确认的条件 + 赔付资格口径。
- **负责任博彩**：自我排除四档（30 / 90 / 180 天 / 永久）选中即出红色警示 + `--redSolid` 确认按钮，期内不可撤销、到期手动恢复；限额提醒三行（仅提醒不代扣，toggle）；求助卡（地区热线，BYDP 不提供咨询）。排除期内隐藏优惠 / 领码 / 前往官网，查验与投诉不受影响。
- **隐私与数据**：「我们保存了什么」**五行**（身份哈希+密文 · 账号哈希 · 证据原文仅仲裁员 · 日志只追加 · **设备标识**，2026-10-01 加）；设备行文案：「**设备标识**：登录时在你的浏览器放一个随机设备编号（Cookie `bydp_did`，400 天），我们只保存它的哈希，用来发现同一设备上的多个账号；不采集浏览器特征，不用于广告。清除 Cookie 即重置；注销后 180 天内删除。」注销说明加一句：「注销前请先结束进行中的投诉。自我排除期内也可注销，但同一 TG / 邮箱在排除期满前（永久排除则永不）不能重新注册。已结案投诉的证据原文会在注销时删除，只保留哈希。」登录页被身份封禁拦下时显示：「该登录身份处于自我排除期内，暂不能注册或登录。」（0013 落地后，D-016 顺带）Cookie 说明并入隐私政策页（上线前置 #10，协调官出稿，锚点 `/privacy-policy#cookies`），M3 不单建 Cookie 页；数据请求三项（脱敏 / 删除原文 / 导出，7 天处理期）；**注销 = 匿名化**：清身份与联系方式、账号哈希与积分归零、动态断开归属；公开案件摘要、状态日志、证据哈希、佣金账本保留但不再关联；需二次验证。
